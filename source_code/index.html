Cryptographic Hashing

Compare SHA-256 and Keccak-256 (Ethereum) hash functions in real time. Even a single character change produces a completely different hash: this is the avalanche effect.

Understanding the Algorithms

SHA-256 is part of the SHA-2 family designed by the NSA. Bitcoin uses SHA-256 for block hashing, proof-of-work, and Merkle trees. It produces a 256-bit (64 hex character) digest.

Keccak-256 is the original Keccak submission that Ethereum uses. It is not the same as NIST's standardized SHA3-256. Ethereum adopted Keccak before NIST finalized SHA-3. The hex output is also 64 characters.

ECDSA Digital Signatures

Generate key pairs, sign transactions, and verify signatures using ECDSA on the secp256k1 curve, the same curve used by Bitcoin and Ethereum.

Security Notice

Private keys are generated and used exclusively in your browser. They are never transmitted to the server. This is an educational demonstration: do not use these keys for real cryptocurrency transactions.

Step 1: Generate ECDSA Key Pair

Generate a new secp256k1 key pair. The private key signs transactions; the public key verifies signatures.

Nonce Safety: ECDSA requires a unique random nonce (k) for every signature. The elliptic.js library uses RFC 6979 deterministic nonce generation, safely deriving k from the message and private key, which eliminates nonce reuse risk.

Merkle Tree Construction

Build and visualize a binary Merkle tree. Transactions are hashed into leaf nodes and paired recursively until a single Merkle root is computed. Click any leaf to generate its Merkle proof.

Why Merkle Trees?

Merkle trees allow efficient verification of transaction inclusion in a block without downloading the entire block. A Merkle proof requires only O(log n) hashes, making them essential for lightweight (SPV) blockchain clients.
